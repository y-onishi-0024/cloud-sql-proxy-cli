# DBツールへの接続設定直接登録の設計案

状態: 2026-10-19に設計・計画と直列実装を承認済み。同日の追加承認でDBeaverのみ専用追加JSON方式に補正。Windows実機確認は利用者が後日手順を実行する。

## 目的と範囲

ファイルを手動インポートする手間を減らすため、csqlからpgAdmin・DBeaver・A5:SQL Mk-2へ接続設定を追加する。既存のファイル出力・接続URI、DBパスワードを保持しない方針、Proxyの接続管理を維持する。

基準はmain `25c63fbf474f022e28269c4057fabea7c4e20bfc`。直前のF2更新入口を含む。承認された実装・独立レビュー・最終検証を進める。push・PR・mainマージ・Release公開・端末更新・利用者の実設定への試験登録を含めない。PC間移行とは別機能とする。

対象は同じPC上のデスクトップ版。pgAdminはPostgreSQL、DBeaverとA5はPostgreSQL・MySQL・SQL Server。Mac/WindowsのpgAdminとDBeaver、Windows amd64のA5通常モードを初期候補とする。Docker/Web版、A5ポータブル版・Store版、DBeaver PRO各版、Linuxの直接登録は初期対象外。既存のファイル出力は残す。

## 確認できた事実と未確認事項

| ツール | 確認済みの入口 | 実装前に確定する事項 |
| --- | --- | --- |
| pgAdmin | 同梱Pythonから`setup.py load-servers`。追加が既定で、`--replace`は全置換。対象DBは`--sqlite-path`、所有ユーザーは`--user`で指定 | 同じインストールのPythonとsetup.py、対象設定DBとdesktopユーザー、初期化済みDBのスキーマ・前後照合 |
| DBeaver | `-con`に単一引数で接続情報を渡す。`create=true|save=true|connect=false`で保存する指定が可能 | Community版のドライバーID、保存先workspace/General、保存完了時点、終了コード・プロセス寿命 |
| A5 | `/AddDB`は同名をエラーにする追加、`/SetDB`は上書き。接続文字列は既存出力の内容を利用可能 | 通常モードの設定保存先、`/Exit`を含む現行安定版の挙動、重複エラーと永続化の判定 |

このMacのpgAdmin 9.18はアプリ内のsetup.py・Pythonの配置を静的に確認した。実際の設定DBの読書き、Python実行、インポートは行っていない。同梱setup.pyのload/dumpには例外を表示して終了する実装があるため、終了コード0だけでは成功にしない。DBeaver・A5の実機検証は未実施。

DBeaver 26.0.2には`-con`の修正履歴があるため、古い版まで一律に対応としない。pgAdmin 9.18、DBeaver Community 26.0.2以降、A5 2.16.0以降の安定版を検証候補とする。この数字は動作保証ではなく、段階0でOS別の実検証版と許可範囲を固定する。

## 方式の比較と推奨

1. **公式の登録経路を使う（採用）:** pgAdmin/A5は登録コマンド、DBeaverは公式の追加JSON読込みを使う。検出・重複検査・結果照合はcsqlが担当する。
2. 既存の設定ファイル/レジストリをcsqlから直接編集する: 起動時間を抑えられるが、版差・保存競合・資格情報破損のリスクが増えるため採用しない。設定の読み取りとバックアップは行う。
3. コマンド表示/コピーだけ: 安全な補助にはなるが、自動登録という目的を満たさないため、ファイル出力とともに失敗時の代替とする。

初期版は対象ツールを利用者が閉じた状態で登録する。pgAdminの設定DB競合、DBeaverの別workspace/選択中プロジェクトへの転送、A5の既存プロセスへの転送を推測で処理しないためである。csqlは対象ツールを強制終了しない。DBeaverはcsql専用の追加JSONだけを書き、GUIは起動しない。画面には「追加設定ファイルを保存。DBeaverで読込みを確認してください」と表示し、実アプリでの読込み完了と区別する。起動中ツールへの登録は別の後続改善とする。

## 利用者の操作

- Ctrl+Kに行操作「ツールへ直接登録」を追加する。接続一覧と保存済み設定の選択行から利用できる。既存Ctrl+Eは「ファイルへエクスポート」として挙動を維持する。
- 対象ツール選択 → 検出した実行ファイル・登録先を確認/修正 → 追加内容と注意事項の確認 → 登録 → 結果表示。未導入・対象外OS/DB/版は理由を表示し、ファイル出力へ戻れる。
- 保存済み設定からはProxy未接続でも登録できる。接続一覧では名前が未保存なら先に保存を案内し、停止処理中・Port未確定なら開始しない。
- 確認画面は既定「取消」。登録名、DB種別、127.0.0.1とPort、DB/User、対象ツールの版・実行ファイル、登録先、必要なバックアップ先を表示する。長いパスはPgUp/PgDnで読める。
- 実行中もProxyは維持する。Escは実行前には無変更で戻る。開始後は結果確認の中断として扱い、追加が取り消せたと断定しない。Ctrl+Cの画面全体終了は既存どおり自画面のProxyだけ停止する。
- 成功・登録済み・競合・結果未確認・失敗を区別し、元のタブ・検索・選択へ戻る。DBログインの成功とは扱わない。

CLIは次を提案する。

```sh
csql profile register dev --tool pgadmin
csql profile register dev --tool dbeaver --dry-run
csql profile register dev --tool a5 --executable "C:\\Tools\\A5M2\\A5M2.exe"
```

`--tool pgadmin|dbeaver|a5`を必須とし、登録対象は保存済み設定1件。`--executable`、`--pgadmin-sqlite`、`--pgadmin-user`、`--dbeaver-workspace`で標準配置以外を指定できる。pgAdminの実行ファイル指定はアプリ/インストールルートを指定し、その内側のPythonとsetup.pyを対として解決する。ツールに無関係なオプションは拒否する。

`--dry-run`は設定ファイルの限定的な読取りと静的検出だけで、外部プロセス起動・一時ファイル・登録履歴・バックアップ・ツール設定変更を行わない。pgAdminのサーバー定義/スキーマ検査は同梱Pythonが必要なため、この時点では「確認後に検査」と表示し、重複なしと断定しない。実登録はTTY確認必須で、`--yes`や非対話からの登録は初期版では用意しない。

## 検出・重複・機密情報

- 自動検出はPATHとOSごとの既知配置に限定する。Macのアプリ内シンボリックリンクは正規化し、同一アプリ配下の通常実行ファイルへ解決する。複数候補・任意のPython設定による保存先変更は黙って選ばず、対象を確認させる。未導入ツールのダウンロード/自動インストールはしない。
- pgAdminの標準候補はMacの`~/.pgadmin/pgadmin4.db`、Windowsの`%APPDATA%\\pgAdmin\\pgadmin4.db`。既存・初期化済みの通常ファイルだけを対象にする。設定DBがない場合は、一度pgAdminを起動して初期設定を済ませて閉じる手順を案内する。
- DBeaverは選択したworkspaceのGeneralプロジェクトを対象とする。対象不明・未初期化・リンク先不明・未対応形式なら登録しない。A5は段階0で確認した通常モードのHKCU保存先だけを扱う。
- pgAdmin/DBeaverの登録名は既存エクスポートと同じ`csql / project / profile`、A5は`csql/project/profile`。同名・同じHost/Port/DB/User/driverなら無変更で「登録済み」、同名異内容・同名複数なら追加せず競合として案内する。保存先が異なれば別対象とする。
- ポートを変更した設定の再登録でも自動上書き/自動改名しない。旧値と新値を示し、ツール側で既存設定を修正するか、別名で保存して登録する手順を案内する。
- A5の`;`・`"`など、接続文字列の構造を変え得る文字を推測でエスケープしない。対象版で形式が確認できない値は拒否し、既存のCSV/JSON/URI出力を案内する。引数は常に配列で渡し、shell/cmd/PowerShell経由で組み立てない。
- パスワード・Google認証・秘密鍵を収集/設定しない。DBeaver追加JSONにはパスワード・接続時コマンド・自動接続指定を含めず、`save-password=false`を設定する。A5は`/Connect`を渡さない。pgAdminの`--replace`、A5の`/SetDB`・削除コマンドは使用しない。
- csqlの設定領域に`db-tools.json`（同意済みの機械固有パス）と`db-tool-registrations.json`（対象・設定ハッシュ・試行状態）を保存する。PC間移行ファイルに含めない。履歴だけで登録済みと判定せず、必ず実際の登録先を読み取り照合する。
- 履歴/バックアップの読書きはcsql内の排他と原子的保存を使う。確認中は排他しない。実行直前に対象の存在・版・プロセス状態・保存先・設定指紋を再検査する。指紋が変われば確認へ戻す。

## ツール別の実行と完了条件

**pgAdmin:** アプリ専用Pythonとsetup.py、明示した`--sqlite-path`・`--user`を使う。確認後、利用者がツールを閉じたことを再検査し、同梱Pythonの標準sqlite3から読み取り専用接続で整合した設定DBバックアップを取得する。単なる.dbファイルコピーに頼らない。バックアップとは別の作業用コピーに対し公式dump-serversを実行し、重複検査に使う。この段階で既登録/競合を検出したらload-serversを実行しない。取込は既存`profileExport(..., "pgadmin")`のJSONを秘密領域の一時ファイルへ保存してload-serversへ渡す。取込後のスナップショットから同じ方法で照合し、対象1件の追加と既存サーバー定義の保持を確認してから成功にする。初期化/マイグレーションが必要なDBはload-servers実行前に拒否する。Pythonのsqlite検査自体は固定コード・分離した環境で行い、アプリ設定をimportしない。公式setup.pyが通常読み込むアプリ設定は、確認した実行対象の信頼境界に含める。段階0の実行ではHOME/APPDATA等も一時領域に分離し、ログやセッションを含め利用者の実設定へ触れないことを確認する。

**DBeaver:** 閉じたツールの対象workspace/General/.dbeaverへ、`data-sources-csql-<安定ID>.json`を新規追加する。IDは正規化対象とConnectionName/設定名から生成し、Port変更で別の登録を増やさない。provider/driverは検証済みの固定マッピングを使い、configurationにHost/Port/DB/User/URLと必要なsslmodeだけを記載する。既存の全data-sources*.jsonは重複検査/退避のために読み取るが編集しない。既存の名前/IDで内容が異なるかUserが取得できない場合は競合とし、資格情報を復号しない。同一内容の専用ファイルは無変更。追加は排他と再検査後にexclusive createし、書込後に同一内容を読み取って「追加設定保存済み」とする。DBeaverへの実読込み・終了後の保持は別の実機gateで確認し、ファイルの保存だけでGUI取込完了とはしない。

**A5:** 既存A5出力のBOM・登録名・接続文字列・末尾改行を構造として分離し、`/AddDB`の1引数へ渡す。曖昧な文字列分割で別のキーを作らない。`/Exit`は段階0で副作用を検証した呼び方だけ採用する。Windowsの通常モード設定を読み取り、対象の追加と既存定義保持を確認する。終了コード/GUIダイアログだけで成功にせず、追加が確認できなければ結果未確認とする。

## 実行状態とバックアップ

確認 → 再検査/排他 → バックアップと重複検査 → 履歴`pending`の永続化 → 公式登録コマンド起動（DBeaverは新規ファイル確定） → 登録先照合 → `verified`または`unknown`。同一設定は登録コマンド起動前に`already-present`、同名異内容は`conflict`で終える。登録コマンド起動前エラーは`failed`/取消、起動後のタイムアウト・終了・照合不能は`unknown`を基本とし、自動再試行しない。

外部書込み前にバックアップ先とpending記録の両方を確保できなければ実行しない。DBeaverではファイル確定をCommittedとして扱い、実GUI確認は別とする。CLI/workerの結果は配送前から保持し、TUI終了後にも要求送信済み・追加確認済み・履歴保存失敗・未確認を報告する。外部追加成功後の履歴保存失敗を「未登録」と表示して再登録を勧めない。結果未確認時は対象ツールの終了を利用者に案内し、閉じた状態で実保存先を再照合する。遅れて登録される可能性が残る間は、定義が見つからなくても再送しない。

バックアップは`ConfigDir/db-tool-backups/<tool>/<UTC日時と一意ID>/`、一時入力は`CacheDir/db-tool-register/<一意ID>/`。確認時・完了時に実際の絶対パスを表示する。pgAdminはSQLiteの整合したスナップショット、DBeaverは対象Generalのdata-sources*.jsonと既存credentials-config.json（復号なし）、A5は検証済みの登録先に限定した設定スナップショットを退避する。新規ディレクトリはUnix0700、ファイルは0600、Windowsは現在の利用者に限定する。バックアップに元ツールの機密設定が含まれ得るため、Git・移行ファイル・ログには含めない。一時ファイルは処理の所有権解放後に削除し、バックアップは自動削除しない。

復元は利用者がツールを閉じて確認する手順を表示する。外部ツールの保存はcsqlと単一トランザクションにできず、取消後に追加される場合もあるため、自動ロールバック・全体置換で他の更新を消さない。既存接続定義の変化を検知したら成功ではなく要確認として、対象・差異の項目・バックアップ先を案内する。

## 検証と受入条件

1. 全3ツールの入口、対象OS/DB、通常/独自配置、未導入/未初期化/複数候補を区別できる。
2. 既定取消とdry-runでは外部プログラムを起動せず、設定・履歴・一時領域を書き換えない。
3. 初回追加、同一再登録、同名異内容、Port変更、外部での削除/変更を観測可能な結果で区別し、勝手な上書き/改名/重複追加を行わない。
4. 入力値を使った引数/接続プロパティ注入を防ぎ、パスワードなし・接続開始なしを確認する。
5. 取消・タイムアウト・終了コード0のエラー・要求後のcsql終了で結果を失わず、登録先照合なしに成功としない。
6. 複数Proxyと別端末所有の接続、一覧検索/選択、F2更新、4形式出力、PC間移行の既存契約を維持する。
7. 実ツールの破棄可能な設定領域で、初回追加/重複/永続化/既存定義保持/未接続をOS別に確認する。Windows実機確認は利用者が後日手順を実行し、それまでは未検証と明示して自動テスト/クロスビルドと分ける。
