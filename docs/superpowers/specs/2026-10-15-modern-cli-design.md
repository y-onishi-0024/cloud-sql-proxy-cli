# csqlの対話画面・エラー案内・接続設定再利用

状態: 2026-10-15、会話内の改善範囲への承認を受けて作成した設計書。実装前の書面確認用。
起点: `a4965ed66b29e5f18a0d99a78e835633caff394b`、ブランチ `feat/modern-cli-interface`。
既存のCLI・PATH・セットアップアプリの仕様を土台とし、本書で明記した拡張以外は維持する。

## 目的と承認された範囲

利用者はGhosttyやTerminalからCloud SQLへ接続する。現在の検索画面を見やすくし、文字を消した後に表示が残る問題を修正する。
エラーが出た際は、その場で原因と次の操作を判断できるようにする。
接続先ごとの設定を保存し、DBブラウザで毎回接続設定を作る手間を減らす。
本人は同じ端末のpgAdminデスクトップ版を使うが、他の利用者は別のDBツールも使う。

今回含めるものは、端末内のTUI、検索不具合の再現・修正、原因別の対処案内、接続プロファイルとポート再利用、pgAdmin向けJSONと汎用接続URIの出力。
DBツールの内部設定DBへの直接書込み、ツールごとの自動起動、SQL実行画面、DBパスワード管理、IAM DB認証の新規対応、履歴・お気に入りの別機能は含めない。
認証・IAM・API・ネットワーク設定を自動変更しない。Docker版・別サーバーのpgAdminへの接続支援は今回の対象外。

## 選択した方式

| 方式 | 得られること | 負担と判断 |
| --- | --- | --- |
| 既存Go CLIへTUIと共通プロファイルを追加 | 端末からの利用を維持し、既存のProxy管理と複数DBツールをつなげる | 採用。今回の用途と一致する |
| 選択メニューの見た目だけ変更 | 差分が小さい | 接続中のエラーや設定の作り直しが残るため不足 |
| Web画面・独自DBブラウザを新設 | 接続からSQL操作まで一体化できる | 今回の用途を超え、別サーバー・配布・認証の保守が増えるため採用しない |

Go 1.26.9、Cobra、Bubble Tea 1.3.10を継続する。装飾は既に依存にあるLip Gloss 1.1.0を直接利用する。
メジャー版移行や新しいGUIフレームワーク導入は今回の前提にしない。検索入力は既存モデルを更新し、カーソル編集を含む必要最小限の操作を実装する。
通常CLIは引き続きCgoなしでmacOS・Windows・Linuxへビルドする。既存ネイティブセットアップアプリも通常CLIを同梱できる状態を保つ。

## 1. 対話画面

対話端末では代替画面を使用し、検索・フォーム・接続準備・稼働中・エラーを同じTUI内で表示する。終了時は元の端末画面とカーソルを復元する。
描画の担当はTUIだけにする。検索worker、Proxyのstdout/stderr、部分失敗を描画先へ直接書き込まず、状態更新へ渡す。
非TTYではTUIやクリップボード操作を開始せず、既存の一覧出力・明示指定での接続を維持する。
色を無効化する`NO_COLOR`に対応し、色だけで選択・状態・エラーを区別しない。

### 一覧と検索

- 上部に画面名と検索欄、中央に候補、下部に件数・選択中の情報・操作キーを表示する。
- 候補はインスタンス名を主表示とし、プロジェクト・リージョン・DB種別を補助表示する。
- インスタンス名とプロジェクトIDを大文字小文字を区別せず部分一致で検索する。通常CLIの`csql NAME`の既存完全一致優先は維持する。
- 検索中・取得件数・部分的に検索できなかったプロジェクト数を示す。部分失敗は確認でき、全失敗と区別する。
- 初期画面は保存済みプロファイルがあればプロファイル一覧、なければインスタンス一覧。Tabで切り替える。
- プロファイルの一覧は名前・DB名・ユーザー名・接続先名・プロジェクトIDを検索対象にする。
- 入力は文字入力・貼付け、左右/Home/End、Backspace/Delete、Ctrl+Uによる全消去に対応する。↑↓/Ctrl+P/Ctrl+Nで候補移動、Enterで決定する。
- 絞り込み変更時は候補選択を範囲内へ戻す。0件から検索を消した場合も元の全件が復元される。
- 端末の幅・高さを状態に持ち、幅は表示セル数で測る。長い文字列を省略し、一覧高さは利用可能行数から決める。狭い端末では補助項目を縦表示または省略する。
- 60列×16行未満ではサイズ不足の説明と取消操作を優先する。サイズを戻せば同じ検索内容から復帰できる。
- Escはフォームから一覧へ戻り、一覧では取消終了。Ctrl+Cはどの状態からも取消・所有Proxy停止へ進む。

検索文字が残るという報告は未修正。現コードはBackspaceでqueryを更新するが、WindowSizeMsgによるレイアウト調整がなく、通常画面へ可変行数を描画する。
query自体の残留、端末の描画残り、長い行・画面縮小・日本語入力の影響を分けて再現する。原因を確定せず、描画方式を変えただけで修正済みとしない。
修正後は入力→削除→再入力、0件→全消去、長い候補、端末縮小・拡大、日本語で同じ問題が起きないことを確認する。

### 接続とプロファイル入力

インスタンス選択後に対象・ローカルポート・接続方式を示す。DB名とユーザー名はProxy起動そのものには不要なので、保存しない通常接続では入力を強制しない。
Ctrl+Sで「接続設定を保存」を開き、名前・DB名・ユーザー名・ポートを入力する。保存後はそのプロファイルから接続する。
プロファイル選択時は保存値を表示して接続準備へ進む。DB名・ユーザー名をインスタンス名やgcloudのアカウントから推測しない。
フォームの保存完了と実際の接続成功は別々に表示する。検索の取消・フォームの取消では保存しない。

## 2. 接続状態とエラー

TUIの状態は「検索中」「一覧」「設定入力」「Proxy起動中」「Cloud SQLへの接続確認中」「Proxy利用可能」「停止処理中」「停止済み」「エラー」に分ける。
API・プロセス待ちを描画ループで実行しない。取消後のworker結果で次のProxy起動や設定保存を始めない。
接続エラー画面は対処と詳細ログを確認できる状態を保つ。再試行は明示キーで行い、前の所有Proxyの終了・後片付け後にだけ開始する。

### 起動時の確認

Proxyには`--structured-logs`と`--run-connection-test`を渡す。利用するProxyのhelpで両機能を確認し、非対応なら対応版の導入案内を出す。
既存の固定配布版2.24.1は両方を備えることを確認した。版の更新は今回必須ではない。
起動時の接続テストはCloud SQLへの到達を確認するもので、DBユーザーによる認証やSQL実行は行わない。

**readyというログだけでは接続確認済みとしない。** 2.24.1ではreadyログが接続テストより先に出るため、接続テスト成功を受けた後にだけ「Proxy利用可能／DBログイン未検証」を表示する。
起動・接続確認の上限は60秒。確認できないまま上限を超えた場合は所有Proxyを停止して時間切れを案内する。未知の版で期待した完了通知が得られない場合も成功扱いにしない。
利用中に認証・通信エラーが出た場合は「直近の接続試行でエラー」を表示し、過去の起動確認を現在の成功と誤認させない。プロセスが生存していれば、次の明示再試行または停止まで所有し続ける。
DBクライアントのユーザー名・パスワード不一致はProxyから確認できないことを説明する。

既存`status`のrunningは子プロセスの生存を意味する契約を維持する。新しいTUIの到達確認と混同しない文言にする。
署名付きstatus/stopのプロトコル、秘密トークン、所有した子プロセスだけを停止する境界は変更しない。
制御記録は起動中から既存方式で公開できるが、CLIの生存表示をDB接続成功へ読み替えない。

### 案内する内容

TUI・通常出力とも「失敗した操作」「分かった原因」「次の操作」「詳細」を同じ判断から生成する。
判定にはエラーの発生元（gcloud検索／Proxy／ローカル処理）を含める。単に`403`や`invalid_grant`があるだけで全エラーを同一原因へ分類しない。

| 原因の証拠 | ユーザーへの案内 |
| --- | --- |
| ProxyのADCでinvalid_rapt／再認証要求 | `gcloud auth application-default login`、Proxyを再起動して再接続 |
| gcloud検索の未ログイン・再認証要求 | `gcloud auth login`、一覧を再取得。ADCとは目的が違うことを表示 |
| ProxyのADC不足・失効 | 標準の利用者ADCならapplication-default login。明示的な認証ファイル等を使う場合はその設定の確認を先に案内 |
| IAM権限不足を示すAPIエラー | 対象プロジェクト・インスタンスと必要な権限の確認を案内。再ログインだけで直ると断定しない |
| Cloud SQL Admin APIの無効化を示すエラー | 対象プロジェクトのAPI状態と管理者への確認。APIを自動有効化しない |
| ポート競合 | 登録済みポートと`csql status`、別プロセスの確認を案内 |
| DNS・接続時間切れ・Private IPの到達失敗 | ネットワーク、VPN、Private IPへの経路を確認。認証失敗と区別 |
| ツール不足・非対応 | 不足したツールと`csql doctor`／`csql setup --install` |
| 保存・出力先の権限／設定ファイル不正 | 対象パスと復旧方法。読み込み失敗を空の設定として上書きしない |
| 不明なエラー | 分かった失敗操作と詳細、`csql doctor`。推測した復旧コマンドを断定しない |

実際に選択したgcloudが管理版の場合、実行可能な引用済み絶対パスを含む案内を生成する。表示した文字列をシェルへ自動投入しない。
詳細ログは時刻・種別・本文を保持するが、端末制御文字を除去し、認証ヘッダー、アクセストークン、パスワード等の既知の秘密値をマスクする。デバッグのために認証ファイル本文を読まない。
1行は最大64KiB、保持ログは合計256KiB。超過した分を省略したことを表示する。未知のログ形式でもエラーを隠さず、構造化ログの解析失敗だけでProxyを停止しない。
非TTYでは案内と詳細をstderrへ出す。TUIではLで詳細表示を切り替える。取消130、引数不正2、その他の失敗1という終了コードを維持する。
ネットワークを使う認証有効性チェックは`doctor`へ暗黙追加せず、接続時の確認で扱う。

## 3. 共通プロファイルとポート

保存先は既存ConfigDir配下の`profiles.json`、形式はVersion=1とProfiles配列。
各項目は`Name`、既存Instanceの5項目、`Database`、`Username`、`Port`、`PrivateIP`を持つ。パスワード・トークン・サービスアカウント鍵は項目にしない。
名前は英数字で始まる1〜64文字の英数字・`_`・`-`で一意とする。DB名・ユーザー名は空白だけを不可とし、それ以外のUnicodeを許可するが、制御文字と長さ256文字超を拒否する。
保存したDB名・ユーザー名の実在や権限は未検証と表示する。プロファイルはPC内の設定で、別PCのポート予約を保証しない。

ファイルは最大1MiB。所有領域の実ディレクトリ・通常ファイルだけを扱い、リンク先へ書き込まない。Unixではディレクトリ0700・ファイル0600を使う。
読込み・検証・変更・atomicな保存までを単一の排他範囲にし、同時保存による取りこぼしを防ぐ。排他は既存の対応OSを通して実プロセス終了時に解放できる方式を使う。
未知Version、壊れたJSON、重複名、不正なInstance、ポート矛盾を拒否し、既存ファイルを保持する。
通常接続時も保存済みポート予約を参照するため、設定ファイルが壊れていれば理由を出して接続を中止する。ヘルプ・version・既存status/stopまで使用不能にはしない。

### ポートの規則

- 同じConnectionNameのプロファイルは同じPortを共有する。異なるDB名・ユーザー名・PrivateIP指定でも、同じCloud SQLインスタンスのローカル接続先を統一する。
- 異なるConnectionNameへ同じPortを予約する保存は拒否する。同じインスタンスでも公開／Private IP経由を同時に別Proxyとして起動する機能は追加しない。
- 初回保存でportを省略した場合は既存DB別標準ポートから最大21候補を調べ、他インスタンスの保存済み予約と使用中のポートを除いて選ぶ。選択結果を保存前に示す。
- 保存済みインスタンスへ通常の一覧から接続した場合も保存済みPortを使う。未保存のインスタンスは既存の自動選択を続けるが、他の保存済み予約は避ける。
- 保存済みPortが使用中なら、別ポートへ自動変更しない。既存のcsqlが同じインスタンスを所有していると署名付きstatusで確認できれば、そのセッションの利用・停止を案内する。暗黙に制御権を引き継がない。
- 明示`--port`が保存済みPortと違う場合は、登録設定との不一致を説明して中止する。保存済みポートの変更は対象インスタンスの全プロファイルを削除して再登録する明示操作とし、既存DBツール設定の更新が必要と案内する。
- 最後の関連プロファイルを削除するとその予約を解放する。削除だけで稼働中のProxyを停止したり、pgAdminの登録を削除したりしない。
- 空き確認とProxyのbindの間の競合は起こり得る。起動失敗を捕捉し、保存したPortを変更せず競合として案内する。

## 4. コマンドとDBツール連携

| コマンド | 動作 |
| --- | --- |
| `csql`／`csql connect` | TTYでは刷新した一覧・接続画面。既存の引数検索も維持 |
| `csql connect --profile NAME`／`csql --profile NAME` | 保存済み設定でProxy起動。位置引数・`--project`・`--refresh`・`--private-ip`との併用は引数エラー。Portは前記の一致規則 |
| `csql profile add NAME --project PROJECT --instance INSTANCE --database DB --user USER [--port PORT] [--private-ip]` | 指定project内のインスタンスを既存Discoverで取得し、名前が完全一致する1件だけで登録。保存値を表示。既存名は上書きしない |
| `csql profile list` | 保存済み設定の一覧。外部コマンドやAPI呼び出し不要 |
| `csql profile remove NAME` | 対象を表示して確認後に削除。非TTYは確認できない旨で中止 |
| `csql profile export NAME --format pgadmin [--output FILE]` | PostgreSQLプロファイルをpgAdmin取込みJSONへ出力。保存先を指定しなければstdout |
| `csql profile export NAME --format uri [--output FILE]` | パスワードを含まない接続URIへ出力。未対応DB種別は理由を示す |

profile addの必須項目を省略した非TTY呼出しは引数エラー。TTYではNAMEを指定した後、省略した対象・DB名・ユーザー名・Portを対話フォームで入力できる。
プロファイル接続は保存済みInstanceを利用し、一覧APIを毎回呼ばない。Proxyの解決・確認は必要だが、gcloud未導入だけを理由に保存済み設定へのProxy接続を拒否しない。認証案内が必要でgcloudが見つからなければ導入方法も示す。
エクスポート、一覧、削除はProxy・gcloud不要。エクスポートしただけで接続成功とは表示しない。
接続中のTUIからEでpgAdmin JSON、UでURIを表示・出力できる。ファイル出力はパス入力後に行い、URIは端末の文字選択でコピーできる。クリップボードへの自動コピーやOSコマンド追加は今回しない。
`--output`は既存ファイル・リンクを上書きせず、ユーザー指定の既存ディレクトリへ0600で新規作成する。書込み失敗時は今回作った未完了ファイルだけを後片付けし、非0で終了する。

### pgAdmin

PostgreSQLプロファイルをName=`csql / PROJECT / PROFILE`、Group=`csql`、Host=`127.0.0.1`、Port=保存値、MaintenanceDB=DB名、Username=ユーザー名で出力する。
接続のローカル区間に対してSSLMode=`disable`、ConnectionParameters.sslmode=`disable`を設定する。ProxyからCloud SQLまではProxyが暗号化する。
JSONにPasswordを入れない。取込み時に`Remove all the existing servers?`を無効のままにし、対象だけを追加する手順を案内する。
初回はpgAdminのTools→Import/Export Serversで取り込む。次回は同じ保存ポートでcsqlを起動し、pgAdminの登録済み接続を使う。
毎回インポートしない。同じJSONの再取込みでは重複し得ること、プロファイルの削除・再作成でPortが変わったらpgAdmin側も更新が必要なことを説明する。
pgAdminアプリの起動成功を接続完了とみなさず、その内部SQLiteや環境固有のPythonを探して書き換えない。

### 汎用URI

PostgreSQLは`postgresql://ENCODED_USER@127.0.0.1:PORT/ENCODED_DB?sslmode=disable`、MySQLは`mysql://ENCODED_USER@127.0.0.1:PORT/ENCODED_DB`を出す。
標準URLエンコーダーを使い、DB名は単一のpath segmentとしてエンコードする。URIにパスワードを付けない。
SQL Serverはツール間のURL解釈が異なるため、この版では汎用URI出力を未対応とし、Host/Port/DB/Userの接続情報を通常表示する。
各DBツールでURIの取り込み可否は異なる。全ツールで自動登録・自動ログインできるとは案内しない。

## 実装の境界と検証

主要フローは`cli.go`の引数・遷移、`selection.go`の対話画面、`sessions.go`の所有Proxy管理で追える形を保つ。
プロファイルの保存・出力は新規`profiles.go`、エラー分類は新規`diagnostics.go`を基本とする。必要なOS固有排他だけ既存`process_unix.go`／`process_windows.go`へまとめる。
保存・出力は独立した外部契約なので分けるが、画面やエラー種別ごとのhelper/serviceファイルは増やさない。
Proxyイベントの取得・正規化はsessions側、描画はselection側に置く。状態通知とログの上限を分け、ログ詰まりで取消や終了処理を停止させない。
検索の既存並列数・キャッシュの認証分離、setupの確認・PATHバックアップ、制御署名の認証境界を保持する。

受入条件:

1. 文字削除の報告を切り分けて記録し、検索の全消去・再入力・0件から復帰・リサイズ・日本語をfocused testとPTY実操作で確認する。macOSのGhostty/Terminalで確認できた範囲を明示する。
2. 既存署名付きstatus/stop、Ctrl+C、Proxyの異常終了と後片付けが回帰しない。取消後の別Proxy起動、worker残留、raceがない。
3. readyログだけで利用可能にせず、接続テスト成功と失敗・時間切れを別扱いにする。ADC・gcloud・IAM・API・ネットワーク・ポート・不明エラーの対処が一致する。
4. 同じインスタンスで設定・Portを再利用し、別インスタンスの予約競合・実ポート競合・同時保存・壊れた設定・保存失敗を安全に扱う。
5. pgAdmin JSONを一時的な登録先へ取り込み、URIの特殊文字とパスワード非包含を検証する。本人の既存登録を変更しない。
6. 非TTY、NO_COLOR、ヘルプ・引数エラー・終了コード、既存セットアップアプリとの互換性を確認する。
7. 通常CLIの5環境ビルド、3環境セットアップ再生成、focused/race・vet、独立レビューと同一候補の最終gateを実装計画に固定する。未変更部分の有効な証拠は再利用する。

工程はこのチャットの親が設計・実装・修正を継続し、固定候補を別担当が独立レビューする方式を推奨する。UI・Proxy・プロファイルの共有状態が密接なため、実装を複数担当へ分けない。
別のユーザー所有Taskは作成しない。push・PR/MR・merge・deploy、実ユーザー設定への新しい変更、実GCP/DB接続はそれぞれ実行範囲を確認する。
本書の書面確認後に実装計画をまとめる。設計書の作成をコード変更・導入完了と報告しない。
