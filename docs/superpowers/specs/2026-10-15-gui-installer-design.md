# ダブルクリックで起動するcsqlセットアップ

## 目的・承認

2026-10-15の「macOS・Windowsともダブルクリック→確認→導入・PATH設定→完了」という提案に対するユーザーの「OKそれで進めて」を実行する。
Windowsは `csql-setup-windows-amd64.exe`、macOSはIntel/Apple Silicon別の `csql-setup-*.app` を配布物にする。
共通Go処理にOS標準画面を接続する。macOSの選択肢は既に提示した.appを採用する。WindowsもGo製のセットアップexeとし、Inno Setup等によるアンインストール管理を追加する前提にはしない。
通常CLI・gcloud・Proxyの導入契約は既存specを継承する。実装はユーザー領域内の既存setup/PATH操作のみで、管理者昇格は求めない。

## 利用フロー

1. 配布物を開くと日本語のセットアップウィンドウを表示する。起動だけではインストールしない。
2. 内容説明と導入先を表示する。macOSでは対象シェルzsh/bash/fishを選べる。SHELLから初期候補を選び、不明ならzshと表示して利用者が選択できるようにする。
3. 「セットアップ開始」で同梱CLIを一時領域へ準備し、既存ツールを調べて導入案を表示する。
4. CLIの対話確認をGUIの確認待ちへ接続する。主画面のスクロール可能な詳細に配布元・版・ハッシュ・保存先・変更内容を表示し、「表示内容で実行」の明示操作後に進める。
5. 不足する外部ツールの導入成功後、PATH変更案を表示して別途確認する。導入取消/失敗ならPATHへ進まない。
6. 実行中もウィンドウは応答し、操作段階とログを表示する。取消を押す/実行中に閉じる操作をするとcontextを取り消し、終了処理を待って取消結果を表示する。
7. 完了・取消・失敗を区別する。失敗時は成功済み部分と再試行方法を確認でき、同じ画面から再試行できる。成功後はターミナルを開き直し、Googleログインとdoctorを確認する手順を表示する。

「ダブルクリックだけ」は起動方法を指す。変更確認は省略しない。Googleログイン/ADCのブラウザ認証は利用者の操作として残す。
インストール中にウィンドウが即座に消える、画面を閉じた後もバックグラウンドで導入が続く、未完了を成功と表示する挙動を避ける。

## 共通処理

- Appへ明示的な確認コールバックを追加する。GUIが設定した場合のみTTY入力に代わって使う。CLIの非TTY拒否・確認待ち取消・終了コードは保持し、CLIの無確認フラグは作らない。
- セットアップの制御は1つのGo controllerが所有する。状態は未開始/実行中/確認待ち/取消処理中/成功/取消/失敗。1回に1workerだけを起動する。
- workerは既存 `setup(ctx,true)` → 成功なら `SetupPath(ctx,shell)` を呼ぶ。GUI main threadから導入処理を実行しない。
- 確認要求ごとにIDと回答channelを持ち、古いIDの操作や重複操作で次の確認を承認しない。context取消を回答の前後で優先する。
- ログは日本語の既存stdout/stderrを同期付き・容量制限付きで表示する。制御用HTTPサーバー、ブラウザUI、外部画面ライブラリは増やさない。
- Finder起動時の最小PATHはプロセス内で一般的なHomebrew設置先を補完する。利用者のシェル設定は読み取り/実行しない。既存のユーザーPATH順序は保持し、標準システムPATHだけの起動ではHomebrewの設置先を先に探索する。保存するPATHの優先契約は既存処理のまま。
- Windows GUIからのバージョン確認等で不要なコンソールを開かないよう、GUI用runnerだけ外部コマンドの非表示起動を設定する。

## 同梱CLIと配置の境界

GUI実行ファイルをcsqlとしてコピーしない。通常CLIを同梱し、App.Executableをその検証済み一時ファイルへ向けて既存SetupPathを使う。
同梱物はOS/CPU・CLI版・種別・SHA256をmanifestと照合する。欠損・不一致・異なるプラットフォームではユーザー設定へ書き込む前に失敗する。
同梱CLIは0700の一時ディレクトリへ配置し、終了/取消/失敗で削除する。ネットワークからCLI自体を取得しない。
既存のバイナリ所有判定・設定バックアップ・PATH重複/曖昧所有時の拒否を保持する。

## ネイティブUIと成果物

- macOS: AppKitのウィンドウ・スクロール可能な読み取り専用ログ・対象シェル・主操作/取消ボタン。UIはmain thread、Goとの橋渡しは最小限のObjective-C/Cgo。構成ファイルを含む.appに同梱し、CPU別ZIPを作る。
- Windows: Win32のウィンドウ・同等のログ/ボタン/状態表示。GUI subsystemでビルドし、Cgoなしでexeに同梱する。
- UIの状態反映は短い定期処理で行い、バックグラウンドworkerの完了をポーリングで待ってUIを停止しない。キーボード操作、スクロール、ウィンドウを閉じる操作に対応する。
- 通常CLIは従来どおりCgoなしで5環境へビルドできる。GUIファイルはinstaller build tagで分離し、Linux GUIは含めない。
- ビルドscriptが通常CLIを先にビルドし、manifest/payloadを独立した一時ビルド領域へ作ってGUIをビルドする。リポジトリ内へ生成バイナリを追跡追加しない。
- ローカル成果物はmacOSのアドホック署名まで確認する。公開用のDeveloper ID署名・公証、Windowsの証明書署名、配布公開は別の公開工程であり、完了したと表示しない。

## 受入検証

- GUI非TTYで明示承認→導入→別確認→PATH設定が成功し、配置されるのは通常CLIである。
- 起動/開始/各確認での取消、worker実行中の取消、失敗後再試行、重複開始、古い確認ID、部分導入後のPATH失敗を一時領域・偽配布物で検証する。
- payloadのハッシュ/OS/CPU/種別/版不一致と欠損を拒否し、一時ファイルを除去する。
- 通常CLI試験とrace/vet、5環境CLI build、Windows GUI build、macOS 2CPU GUI buildと.app/ZIP構造・manifest一致を確認する。
- macOSで実際にウィンドウを開き、表示・シェル選択・確認待ち/取消または一時ホームでの配置を検証する。実GCP/DB/利用者の実HOMEへ導入しない。
- Windowsの実GUI操作を実行できる環境がなければ、クロスビルド/fixtureと区別して未確認と報告する。

## 対象外

システム領域への導入、権限昇格、Google認証の無人化、サービス常駐、自動更新、アンインストーラー、Linux GUI、公開署名/公証/配布、既存ProxyやDBの操作。
