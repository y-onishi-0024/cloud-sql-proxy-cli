# 新しいPCへの接続設定の移行

状態: 利用者が設計を承認し、実装計画の作成へ進むことを明示した。製品コード・実設定・配布物は未変更。
基準: main/v0.7.0 `f2181c140696fe0936ffc9da6ef426406d76f014`。

## 目的と対象

新しいPCで接続先を登録し直さずに、旧PCのcsqlの保存済み接続設定を再利用できるようにする。
Mac・Windowsで同じ移行ファイルを扱い、OS固有のパスを持ち込まない。Linuxの通常CLIでも同じ形式を使う。
利用者が選択した方式はファイルの受け渡し。以下の競合処理・画面・コマンドを今回の設計とする。

対象は保存済みプロファイル全件の名前、プロジェクト、インスタンス、リージョン、接続名、DB種別、DB名、DBユーザー名、Port、Private IP設定。
保存していない接続は対象外とし、必要なら既存の保存操作を案内する。
Google認証・トークン・秘密鍵・DBパスワード、セッションと制御用秘密情報、ログ、検索キャッシュ、更新通知キャッシュ、ツール実体、導入記録、PATH、DBブラウザ自体の設定は含めない。
移行ファイルにはプロジェクトやDBユーザー名を含むことを出力時に示す。暗号化・パスワード保護・クラウド同期は初版に含めない。

## 方式の比較

| 方式 | 判断 |
| --- | --- |
| 専用のJSONへ接続設定だけを書き出し、確認して追加する | 採用案。受け渡す内容が明確で、OS間移行と版の検査ができる |
| 設定ディレクトリを丸ごとZIP化する | 端末固有の導入記録・セッション等を誤って移すため採用しない |
| クラウドへ同期する | 今回選択されたファイル方式の範囲外。同期用認証・競合処理を新設しない |

## CLIと画面

- `csql migrate export [--output FILE]` を追加する。移行対象件数と実際の絶対保存先を表示する。接続・認証・Google API呼び出しは行わない。
- 出力先を省略すると、既存DBツール出力と同じく起動ディレクトリへ `csql-migration-<UTC日時>.json` を提案する。同名があれば `-2` 以降を付ける。明示した出力先も含め、既存ファイルは上書きしない。
- UIはCtrl+Kの共通操作へ「移行ファイルを書き出す」「移行ファイルを取り込む」を追加する。選択行がなくても利用できる。保存専用の `profile add` 画面には追加しない。
- 画面からの出力は絶対パスを入力済みで表示し、対象件数と含む情報を示してEnterで出力する。CLIは明示した出力操作をそのまま実行でき、非対話でも利用可能とする。
- `csql migrate import FILE [--dry-run]` を追加する。`--dry-run` は追加・同一・競合の一覧と件数だけを表示し、取込用ロックやバックアップを含む設定への書込みをしない。非対話でも利用可能とする。
- 実際の取込は対話端末でのみ行い、既定は取消。`--yes`、自動上書き、全置換、ダウングレード変換は初版に含めない。
- UIの取込はファイルパスのフォームから確認一覧へ進む。UIでは貼付けたパスの両端の対応する引用符1組を取り除き、先頭の `~/` または `~\` を現在ユーザーのホームへ展開する。相対パスは起動ディレクトリ基準で絶対パスにする。`~他ユーザー`、環境変数、シェルのエスケープや式は展開しない。CLIのFILE/--outputはシェル解析後の文字列を通常のパスとして扱う。ネイティブのファイル選択ダイアログやドラッグ操作は追加しない。
- 確認一覧には入力ファイル、取込先、追加件数、同一件数、競合内容、保存前バックアップのディレクトリを示す。長い一覧・パスはPgUp/PgDnで確認でき、Escで戻る。
- 成功後は新しい保存済み一覧を読み直して件数・バックアップ絶対パスを表示する。タブ・検索・選択を可能な範囲で維持する。Proxyの開始・停止・再起動・自動接続はしない。
- 操作中の取消と遅延結果が次のフォームや別操作を上書きしない。ファイル操作の完了を待ってから再試行・画面終了を許可する。書込み確定後に取消が届いた場合は「取消済み」と誤表示しない。

## 移行ファイルの契約

- UTF-8の単一JSON。最上位は `format: "csql-migration"`、`version: 1`、`createdAt`（UTCのRFC3339）、`csqlVersion`、`profiles`。
- 各プロファイルの項目名・入れ子は現行の `Profile` のJSON表現を維持する。任意パス・実行コマンド・導入元URLは受け付けない。
- 移行ファイル全体は最大2MiB。取込後の保存形式は現行 `profileStore` のVersion 1と1MiB上限を維持する。出力時も同じ上限を検査する。
- 未知の形式・版・項目、重複JSONキー、末尾の別JSON、不正UTF-8、過大入力、プロファイル内部の不正値・予約矛盾を拒否する。表示するメタデータも書式・長さを検査し、端末制御文字を表示しない。
- OS間の改行差を許容し、入力のUTF-8 BOMは先頭の1個だけ許容する。出力はBOMなし。空のプロファイル一覧は有効で、読込先を消去しない。
- JSON内の値をコマンドやシェルとして実行しない。内容の正当性はGoogle APIで検証しない。新PCで実際に接続するときに既存の接続・権限検査を使う。
- 入出力は通常ファイルに限定し、シンボリックリンク・親のリンク・特殊ファイルを拒否する。容量を制限して読込み、確認後は検証済みの内容を保持して適用する。パスだけを保持して別内容を読み直さない。
- ファイル権限はUnixで0600とする。Windowsでは同じ所有者専用ACLが保証されたとは案内しない。暗号化や配布元認証を行ったとは表示しない。

## 重複とポートの扱い

- 取込は既存設定を保持する追加方式のみ。名前と全項目が一致するものは「同一」としてスキップし、繰り返し取り込んでも増殖しない。
- 同じ名前で1項目でも異なる場合は競合とする。別名でも、異なる接続先が同じPortを予約する場合、または同じ接続先が異なるPortを持つ場合は競合とする。
- 1件でも競合があれば取込全体を適用しない。成功分だけの部分適用、勝手な名前変更・Port変更、既存優先での黙った除外は行わない。
- 競合は該当の設定名・接続先・Portと理由を一覧化する。保存済みPortの変更には既存の `csql profile update NAME --port PORT` を案内し、名前変更や内容修正が必要な場合は移行元で設定を修正して再出力する手順を示す。自動で設定を削除しない。
- ここでいうPort競合は保存済み予約間の矛盾を指す。新PCの他アプリによるPort使用状況は接続時に検査する。取込のためにTCPを待受せず、既存の接続を止めない。保存したPortを空きPortへ自動変更しない。
- DB種別などのメタデータは各設定の値として維持する。同一接続先・同一Portの別名プロファイルは、現行制約どおり許容する。

## 排他・バックアップ・失敗時

- 事前確認で読み込んだ既存プロファイルの内容を捕捉し、確認後に既存の `profiles.lock` を取得して再読込する。変化があれば何も適用せず再確認を案内する。確認画面を開いている間はロックしない。
- 新規追加が0件なら、バックアップ・設定保存を行わず「変更なし」と表示する。競合・入力不正・事前確認取消でも設定へ書き込まない。
- 追加がある場合は、ロック下で既存 `profiles.json` の通常ファイル確認と内容を再検査し、原本バイト列のバックアップをConfigDir直下の一意な `profiles.pre-import-*.json` へ新規作成する。既存ファイルを上書きしない。Unix権限は0600。
- バックアップの書込み・closeが完了するまで本体を書き換えない。バックアップを確保できなければ適用を止める。初回導入で元ファイルがない場合は、元設定がなかった旨を表示しバックアップを作らない。
- 現行の原子的なJSON保存を使い、設定を全件まとめて確定する。バックアップ作成後に保存が失敗しても元設定を保ち、バックアップが残った場合は場所を案内する。成功を表示しない。
- 設定保存が確定する直前に取消を確認する。確定後は成功として扱い、終了時も結果とバックアップ先を伝える。電源断時の完全な永続性は保証しない。
- バックアップは自動削除しない。復元が必要な場合は、csqlを終了してから表示したバックアップを同じConfigDirの `profiles.json` へ戻す手順を示す。任意の移行ファイルをそのまま設定本体へコピーする案内はしない。
- 別端末の稼働セッション、セッション制御情報、Google認証・ツール・PATH・更新記録は変更しない。

## 移行後の案内

完了画面は、設定の移行とGoogle認証・依存ツールの準備を区別する。
新PCでは既存の `csql doctor` / `csql setup` / `csql setup --install` を案内する。
Googleログインは既存の診断が示す実際のコマンドから行う。取込操作はログインやツール導入を実行しない。
pgAdmin・DBeaver・A5側の設定やパスワードは含まれないため、新PCのcsqlから必要な形式を再出力する案内を出す。

## 実装と検証の範囲

主要な移行処理は新しい `migration.go`、既存のプロファイル保存境界は `profiles.go`、CLI入口は `cli.go`、画面は `selection.go` を中心にする。
入力検査・プレビュー・保存をUI/CLIで共有し、入出力ごとの小さなhelperファイルや依存ライブラリは増やさない。既存LoadProfilesのエラー契約と現行保存形式を維持する。
状態と排他が連動するため同じ実装担当が直列で実装し、独立Reviewer1名が全差分を確認する。実装・独立レビュー・最終検証の実行範囲は実装計画で確認する。
公開・push・PR・mainマージ・Release・この端末の更新・実設定の移行は今回の設計承認だけでは行わない。

受入条件:

- 一時的な旧PC/新PC領域で全項目を往復でき、Mac・Windows向けの同一ファイルで値を維持する。実認証・実DB・利用者の設定を使わない。
- 空、新規全件、完全同一の再取込、同名異内容、同Port別接続、同接続別Port、入力内の矛盾、確認中の別保存を検証する。拒否時に元設定が変わらないことを確認する。
- 不正形式・版・未知項目・重複キー・過大入力・BOM・制御文字・リンク/特殊ファイル・既存出力衝突を検証する。
- バックアップ失敗、設定保存失敗、取消、適用後の終了を観測し、既存設定の保持と正しい結果表示を確認する。
- UIの選択0件、パス編集/検索消去、既定取消、スクロール、エラー後の再試行、稼働接続保持、保存一覧更新、遅延結果・終了競合を検証する。
- 最終gateは同一レビュー済み候補の全体race・通常/installer vet・installer既存テスト、Mac/Windows/LinuxのCLIとMac/Windows installerのビルド・同梱一致、auto/light/NO_COLORの一時領域PTYを実装計画で定める。Windows実機がなければ未確認として区別する。
