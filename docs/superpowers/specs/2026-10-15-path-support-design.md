# csql と管理版ツールのPATH設定

## 目的と正本

利用者が配置元のディレクトリを離れても `csql` を実行でき、管理版 `gcloud`・`cloud-sql-proxy` もコマンド名だけで呼び出せるようにする。
ユーザーの2026-10-15の追加依頼と「3コマンドをまとめて対応」の回答が正本。
本仕様は初期設計の「CLIからシェル設定を書き換えない」を、明示的なPATH設定操作に限って変更する。
通常の接続・診断・インストールだけではPATH設定を書き換えない。

## コマンドと受入条件

- `csql setup` は現行の案内に、実際の配置先と `csql setup --path` の案内を追加する。書き込みなし。
- `csql setup --path` は起動中のcsqlをユーザー設定領域の `csql/bin/csql`（Windowsはcsql.exe）へコピーし、そのディレクトリと導入済み管理版ツールのディレクトリをPATHへ登録する。
- `csql setup --install --path` は不足ツールの導入成功後にPATH設定へ進む。インストールとPATH変更をそれぞれ確認する。入力の先読みで2回目の回答を失わない。
- `--shell zsh|bash|fish` でUnixの対象シェルを指定できる。省略時はSHELLから検出する。Windowsでの指定や `--path` なしの指定は入力不備とする。
- 変更先、コピー元・先、追加ディレクトリ、設定内容、バックアップ方法を表示し、対話端末で明示確認してから書く。非対話・取消・確認前のcontext取消では書かない。
- 管理版が未導入なら、そのツールは追加せず不足を表示する。既存のPATH上のツールは移動・コピーしない。
- 登録対象の管理版はinstalled.jsonの安全な相対パスと起動確認を使って検証する。WindowsのgcloudはPythonではなく公式SDKのbinディレクトリを登録する。
- 既存PATHを先に保持し、新しいディレクトリは後ろへ追加する。衝突する既存コマンドが優先される場合は表示する。
- 再実行は登録を重複させず、管理版の版変更はcsqlが登録した旧ディレクトリだけを更新する。既存のユーザー設定・PATH項目を消さない。
- 現在の親シェルへ反映済みとは表示しない。端末再起動と確認コマンドを案内する。

## OSごとの保存方法

### macOS・Linux

- zsh: ZDOTDIRがあればその `.zshrc`、なければホームの `.zshrc`。
- bash: `.bashrc` と、ログイン時に実際に使われる最初の `.bash_profile` / `.bash_login` / `.profile`。いずれもなければ `.bash_profile` を作る。既存の設定を実行せず、内容を保存したまま専用の開始・終了マーカー付きブロックだけを更新する。
- fish: XDG_CONFIG_HOMEまたはホームの `.config` 以下の `fish/conf.d/csql.fish`。`fish_add_path --append --path` と安全な文字列引用を使い、既存コマンドの優先順位を保つ。
- 未対応シェルは自動変更せず、追加すべきディレクトリと手動設定手順を案内して非0で終了する。
- 複数シェルを一度に設定しない。利用者が `--shell` を指定して必要なものだけ実行する。

### Windows

- HKCU\\Environment のユーザーPathだけを更新する。システムPathは変更しない。
- 展開前の値とREG_SZ/REG_EXPAND_SZの種類を保持し、既存項目の順序を変えない。ディレクトリの同一判定は大文字小文字・末尾区切りと環境変数展開を考慮する。
- csqlが新たに登録した項目を記録し、更新時に除去するのはその旧登録項目だけとする。元から存在した項目を所有扱いにしない。
- 変更前のPathと種類をバックアップし、設定変更通知を送る。通知失敗と保存失敗を区別し、既存端末が反映済みとは表示しない。

## 書き込みの境界

- 自動変更は明示確認済みのユーザー領域に限定し、sudo・システム設定・ログイン・GCP操作は行わない。
- csqlのコピーと設定は一時ファイルから配置する。管理binはユーザー専用、バイナリはUnix0700。
- 既存の同一バイナリは再利用する。別内容のファイルは、前回csqlが配置したものと記録のハッシュが一致する場合だけ更新し、それ以外は上書きせず理由と対処を返す。
- 既存シェル設定の内容と権限を保持する。存在するファイルは一意なバックアップへ保存する。
- シンボリックリンク、非通常ファイル、壊れた/重複したマーカー、csql所有と確認できないfish設定への書き込みは拒否し、手動手順を表示する。
- 制御文字、PATH区切り文字など表現できないディレクトリは拒否する。空白、日本語、引用符、ドル記号は安全に扱い、評価対象のコードへ未引用で差し込まない。
- 同時実行をロックで拒否し、読み取り後に設定が変わっていたら上書きしない。部分失敗時は変更済み/未変更とバックアップを表示し、全体成功とは扱わない。
- バックアップからの復旧方法とマーカー部分の削除方法をREADMEへ記載する。自動削除コマンドは今回含めない。

## 検証と残る実機確認

一時ホームで実際のzsh/bashを起動し、csqlと偽ツールの名前解決、再起動後・繰り返し起動での重複なし、既存優先を確認する。
確認取消/非TTY、危険な文字、リンク、設定の同時変更、バックアップ、再実行、管理版更新、2回確認、部分失敗はfixtureで検証する。
Windowsは保存APIを分離したfixtureでユーザーPathの値・種類・所有項目・通知を検証し、Windows向けビルドも行う。Windows/fishの実行環境がなければ実機未確認と明示する。
利用者の実ホーム・実ユーザーPathには開発検証から書き込まない。
