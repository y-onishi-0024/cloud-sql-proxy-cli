# 保存済みポートの編集と接続一覧での操作

状態: 2026-10-16に利用者が設計を承認し、実装計画の作成へ進むことを明示した。製品コードは未変更。接続中のポート変更は「停止してから変更」で確定した。
基準: 公開main `53942fbe2ed1fd7b2efedabcfc46b079eb9179ee`（v0.4.1）。

## 目的

保存済み接続設定を削除・再登録せずにローカルポートを変更できるようにする。
接続のたびに詳細画面へ移動する操作を廃止し、一覧を見ながら接続ごとの出力・ログ・保存・停止を扱えるようにする。

## 方式の比較

| 項目 | 推奨方式 | 他の方式との差 |
| --- | --- | --- |
| ポート編集 | ポート変更専用の操作を追加し、同じインスタンスの設定をまとめて更新 | 汎用設定エディターより範囲を絞れ、既存の名前・DB・ユーザーを保てる |
| 接続後の画面 | 接続一覧へ移り、行を選んで操作 | 従来の詳細画面に一覧への戻りボタンを増やすだけでは、画面遷移が残る |
| 接続中の変更 | 停止を確認してから変更（利用者が選択済み） | 自動停止・再接続はDBツールの接続を切るため採用しない |

## 保存済みポートの変更

- 保存済み設定タブ、接続一覧の操作メニューから「ポート変更」を開く。現在のポートを入力済みにする。
- CLIでも `csql profile update NAME --port 15432` を追加する。更新対象はポートだけとし、範囲は1〜65535とする。
- 対象の設定名、接続先、変更前後のポート、同じインスタンスを共有する設定名を表示する。画面では内容確認後の確定操作で保存する。
- 同じインスタンスの複数DB・ユーザーは現在1つのポート予約を共有しているため、該当する保存済み設定を1回の書き込みでまとめて変更する。
- 設定名、DB名、ユーザー名、接続方式、保存形式Version 1は維持する。同じ値への更新は変更なしとして扱う。
- 他インスタンスの保存予約、起動中の予約、実際の待受と競合する新ポートには変更しない。失敗時は設定全体を元のまま保持する。
- 管理中Proxyが起動中・稼働中・停止処理中なら、対象セッションと停止方法を案内し、設定を書き換えない。別端末が起動したProxyも同じ扱いとする。応答を確認できない対象記録がある場合も変更を中止する。
- 同版csqlの起動とポート編集は、設定読み込みから管理セッション登録までの起動区間と、更新検証から保存までの区間を同じプロセス間ロックで直列化する。稼働状態の確認後に別の起動がすり抜ける競合を防ぐ。
- ロック中に保存済み設定を再読込し、画面で確認した旧ポートと違う場合は再表示を求める。同時編集を黙って上書きしない。
- 停止・エラー後の画面内接続にも新しい設定を反映し、一覧のポート表示と次回再接続を揃える。過去のログは保持する。
- 変更後はDBツール側のポート変更または再エクスポートを案内する。DBツール内の設定は直接書き換えない。

## 一覧を基本にする操作

- インスタンス・保存済み設定から接続を追加すると、接続一覧へ移り、その接続を選択する。起動中・成功・失敗・個別停止の通知で詳細画面へ自動遷移しない。
- 接続一覧で上下キーにより選択し、Enterで選択行の操作メニューを開く。メニューにはエクスポート、ログ、保存、ポート変更、停止、再試行を表示する。
- 直接操作は `Ctrl+E` エクスポート、`Ctrl+L` ログ、`Ctrl+S` 保存、`Ctrl+D` 停止、`Ctrl+R` 再試行を用意する。ポート変更はメニューから選べる。
- 検索は従来どおり文字入力で行う。E・L・Sなど通常文字を入力しただけで操作を発火しない。フォーム・出力先入力中の通常文字も入力として扱い、既存の確定・取消操作を維持する。
- 操作対象は検索後の一覧で選択した行とする。以前開いた接続や、フィルターに隠れた行を操作しない。
- 対象行がない場合は操作を実行せず案内する。停止済み・エラー行も一覧に残す。
- エクスポートは既存のツール選択→自動入力済み保存先を再利用する。未保存の場合は保存への案内を出す。
- 保存は既存の新規・別名保存フォームを一覧から開けるようにする。保存済み設定のポート編集は専用操作で行う。
- フォーム・メニューの確定や取消後は、起点のタブ・検索文字・選択行を維持して一覧へ戻る。出力先のEscはツール選択へ戻る。
- 保存・出力・編集を開いた時点の接続ID、試行番号、設定、実ポートを保持する。他の接続の終了通知で対象や入力内容を切り替えない。
- 停止・再試行は選択行だけを対象とする。Ctrl+Cでこの画面が起動した全Proxyを停止し、他の端末のProxyは維持する。
- インスタンス・保存済み設定から接続を追加する既存の3タブ構成を維持する。インスタンス・保存済み設定タブのEnterは接続のままとする。

## ログ・対処案内と画面サイズ

- 広い画面は左に接続一覧、右に選択接続の情報・ログ・対処案内を表示する。
- 狭い画面は一覧とログを縦に配置し、選択行を見失わないようにする。最低60列×16行で選択行・状態と操作ガイドを残す。
- ログを表示したまま選択接続を切り替えられる。ログはPgUp/PgDnでスクロールし、上下キーは一覧の選択に使う。
- エラー時は選択接続に原因と次の操作を表示する。背景接続の失敗で現在のフォーム・選択・表示を奪わない。
- 新版通知、NO_COLOR、日本語入力、検索の文字消去、端末の画面復元を維持する。

## 守る境界

保存済みポートの自動移行は追加しない。編集を実行した対象だけを変更する。
認証通信・秘密トークン・制御プロトコル・実GCP設定・実DB・他アプリの設定を変更しない。
既存のpgAdmin、DBeaver、A5、URIの形式・非上書き保存を維持する。
汎用設定編集、常駐サービス、他端末のログ取り込み、依存追加は含めない。

## 検証と進め方

1. CLIから旧5432の保存設定を15432へ変更し、同じインスタンスの全設定・再起動後の読込み・4形式の出力が新ポートになることを確認する。
2. 使用中・保存予約・起動中・応答不明・同時編集・取消・不正値で保存内容を破損しないことを検証する。
3. 別プロセスによる起動と編集を競合させ、起動が旧設定を読んだ後に更新だけ成功する状態を防ぐことを検証する。
4. 複数接続で一覧から保存・出力・ログ・停止・再試行を行い、背景終了や検索後も対象が混線せず、他の接続が継続することを確認する。
5. カラー／NO_COLOR、広い画面／60列×16行、日本語検索と消去、フォームの戻り先、Ctrl+Cによる所有接続の終了をPTYで確認する。
6. 実装後に独立レビューと同一候補での全体race・vet、Mac・Windows向けビルドを行う。実DBへの接続は今回の自動検証には含めない。

状態が連動するため、設計・実装は現在の担当が直列に継続する。別Taskは作成しない。実装担当から独立したReviewerを1名使い、修正時は同じ担当が再確認する。
設計確定後、既存のprofiles.go、sessions.go、connections.go、selection.go、presentation.goと対応テストを中心に実装計画をまとめる。機能ごとの新しいservice/helperファイルは増やさない。
この設計ではpush・PR作成・mainへのマージ・リリース公開・端末の実設定変更は行わない。それらは実装後の明示依頼に従う。
