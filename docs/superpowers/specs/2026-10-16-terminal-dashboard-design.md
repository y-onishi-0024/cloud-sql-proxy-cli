# 接続ダッシュボードの操作・表示改善

状態: 2026-10-16に利用者がこの設計を承認し、実装計画の作成へ進むことを明示した。
基準: 公開main `9fab4bd493ce13a2f5fa96630fd137917dec367c`（v0.5.0）。作業場所は既存checkout、ブランチは`feat/terminal-dashboard`。

## 目的と対象

接続先を比較し、操作を探し、失敗から復旧するまでを一覧中心で進められるようにする。既存の接続後も一覧へ留まる操作を継続する。

対象は固定ヘッダー、検索できる操作メニュー、一覧の列表示、診断と復旧操作、配色・余白。お気に入り・履歴・環境ラベル、接続一覧自体のファジー検索、出力先の記憶、DBツール自動起動、ログ検索・全幅化、自己更新、配布CIは後続とする。

| 方式 | 判断 |
| --- | --- |
| 現在のBubble Tea画面と接続管理を継続し、描画・操作入口を改善 | 採用。既存のID・試行番号・終了順序を使い、操作と見た目の両方を改善できる |
| 色・余白の変更だけに限定 | 操作の発見やエラー復旧の手数が残るため、今回の目的を満たさない |
| 画面基盤の置換や別GUIアプリの新設 | 接続管理とOS別配布への影響が大きく、今回の範囲に含めない |

## 固定する画面構成

- 全画面の最上段をアプリ名・現在の画面名・状態・小さな更新バッジ、2段目を既存の3タブにする。メニュー・フォームでもタブと現在位置を残す。
- 更新通知があってもタブ名を上書きしない。ヘッダーには「更新 vX.Y.Z」を表示し、更新先の完全なURLはF1ヘルプの更新案内に載せる。通知だけのために本文の高さを減らさない。
- 下2行の操作案内は固定する。現在の画面で有効な主要キー、F1ヘルプ、Ctrl+Cによるこの画面の全接続停止を優先する。
- 外枠とペイン間の区切りを中心とし、同じ情報の反復、空の見出し、過剰な空行を減らす。長い出力結果・対処案内のページ送りを維持する。
- 横100列・縦20行以上で左右2ペイン、それ未満は縦配置。最低60列×16行で選択行・状態・検索欄・終了案内を維持し、これ未満ではサイズ案内と終了操作を残す。

## 一覧の列表示

- 広い画面の「接続一覧」だけを、1接続1行の表にする。列は「状態／設定・接続先／プロジェクト／Port／DB」。列幅は端末の表示セル数で計算し、日本語・長い名前を安全に省略する。
- 状態は起動中・確認中・利用可・失敗・停止中・停止済を文字と記号で表示する。「利用可」は現在のProxy利用可能と同じ意味とする。
- 設定名がある行は設定名を優先し、インスタンス名を詳細へ表示する。未保存ならインスタンス名を使う。DB未指定は「未指定」、未確定ポートは「未確定」とし、空欄だけで意味を伝えない。
- 狭い画面は既存の2行表示を改善して使う。表の行順・選択・検索・停止済み行の保持は現行どおりとし、状態変化で勝手に並べ替えない。
- 選択ペインには対象インスタンス、Host:Port、DB・ユーザー、リージョン・DB種別と確認範囲を表示する。長いセッションIDはF1の選択対象詳細へ収める。
- 接続確認は既存の進捗を正本とする。「起動中」「Cloud SQL確認中」「Proxy利用可能」と、常に「DBログイン未検証」を区別する。ログから新しい確認済み状態を推測したり、DBへの追加ログイン検査を行ったりしない。

## 検索できる操作メニュー

- 接続一覧のEnter/Ctrl+Oと保存済み設定のCtrl+Oを、検索欄付き操作メニューへ置き換える。Ctrl+Kでも開ける。インスタンス一覧と検索エラー画面にもCtrl+Kを用意する。
- 一覧の文字入力は従来どおり接続先の検索とする。操作メニュー内の文字入力だけが操作の検索となる。Ctrl+P/Ctrl+Nによる上下移動は維持する。
- 操作の名前・補助語で部分一致検索する。「ポート」「port」「ログ」「log」「コピー」などで見つけられるようにする。新しい検索ライブラリは追加しない。
- 接続一覧は既存の出力・ログ・保存・ポート変更・停止・再試行を継続する。診断があれば復旧コマンドのコピーを加える。保存済み設定は接続・別名保存・ポート変更、インスタンス一覧は接続・保存・一覧再取得、検索エラーは再検索と復旧コマンドのコピーを対象とする。
- 利用できない操作も理由付きで表示する。例: 未保存のポート変更は「先に設定を保存」、稼働中のポート変更は「停止後に変更」、停止中の再試行は「停止完了を待機」。無効項目を確定しても副作用を起こさず理由を残す。0件ではEnterを無操作とする。
- フィルター後の位置を操作の番号として実行しない。各項目を意味のある操作IDに対応させ、検索で順序・件数が変わっても別操作へ向けない。
- メニューを開いた時点の接続ID・試行番号・設定を保持し、確定時に対象と実行条件を再確認する。背景の停止・再試行で対象が変わった場合は再選択を案内し、別の接続を操作しない。
- Escで起点のタブ・検索文字・カーソル・選択行へ戻る。メニュー内の検索で起点の検索を上書きしない。既存のCtrl+E/L/S/D/Rは保ち、同じ実行入口と条件検査を使う。
- フォーム・出力先入力中はCtrl+Kで別操作へ移らない。入力を保存・取消してから操作メニューを開く。

## F1ヘルプ

- 一覧・メニュー・フォーム・エラー画面でF1を押すと、現在位置の操作キー、選択対象、確認範囲、更新案内をページ送りで読める。
- 入力状態や起点の戻り先を独立して保持し、F1またはEscで元の画面へ戻る。ヘルプ表示中の文字入力を元フォームへ送らない。
- 背景の接続・保存完了イベントは処理するが、ヘルプを勝手に閉じたり選択を変更したりしない。Ctrl+Cはヘルプ中でも既存の全終了を実行する。
- ヘルプには認証ファイルや環境変数の値を出さない。セッションIDは既存の管理情報だけを表示する。

## エラーからの復旧

- 選択行のエラーは「失敗した操作／短い原因／次の操作」を優先して表示する。空のDB情報や同じ原因・対処の反復を先頭へ置かない。詳細と生ログは既存のCtrl+Lとページ送りから読める。
- `Diagnostic`へコピー用の復旧コマンドを構造化して保持する。既存の`Next`表示契約を保ち、コマンドを外部ログや自由文から抽出しない。
- 検索認証では`gcloud auth login`、Proxyの通常ADCでは`gcloud auth application-default login`を提示する。明示ADCでは既存の発行元・期限確認を案内し、通常ADCへの切替コマンドを出さない。gcloud未導入時はdoctor・導入の案内を優先する。
- 権限・API無効・通信・ポート競合・ローカル設定・不明エラーも、既存の原因判定を使って短い案内と診断コマンドを示す。IAM付与・API有効化の実行は追加しない。
- 利用者が操作メニューから選んだコマンドだけをクリップボードへコピーする。複数ある場合は1件ずつ選ぶ。画面の折り返しを含めず、既存のUnix/PowerShell用の引用を保つ。
- 認証・導入コマンドを自動実行しない。コピー後に「別ターミナルで実行→戻って再試行」を案内する。検索は同じ検索範囲を明示的に再取得、接続は既存の停止完了を待つ再試行を使う。
- メニュー開始時のコマンドと対象を固定し、コピー実行前に診断・ID・試行番号の一致を再確認する。バックグラウンドの別接続エラーで上書きしない。

## クリップボード境界

- OS別の小さな実装を`clipboard.go`1ファイルにまとめる。メインの状態遷移は`selection.go`に残し、Appに差し替え可能な入口を置く。OS外部コマンドとの独立した検証価値があるため、この境界だけを分離する。
- macOSは`pbcopy`、WindowsはPowerShellの`Set-Clipboard`、Linuxは利用可能な`wl-copy`または`xclip`を使う。コマンドと入力テキストを分離し、テキストをシェルコードへ連結しない。Windowsの日本語はUTF-8として渡す。
- 実行は非同期で最大2秒、連打による同時コピーを抑止する。画面終了時に取消し、worker終了を待つ。完了イベントが別フォームや別対象の結果を上書きしないよう、操作番号と対象を確認する。
- 外部ツール未導入・タイムアウト・失敗でも接続や一覧を維持し、コピー可能なコマンド全文と手動コピー案内を表示する。依存導入、OSC52、クリップボードの読取りやバックアップは追加しない。
- 自動検証では偽実行ファイル・差替え入口・一時設定だけを使い、利用者の実クリップボードを変更しない。

## 配色と余白

- 配色の役割を選択・通常・補助・成功・注意・失敗に統一する。通常文字と補助文字のコントラストを確保し、選択行は背景または反転と選択記号を併用する。
- `CSQL_THEME=auto|dark|light`を対話画面で受け付ける。既定はauto。dark/lightは明示した背景向けのパレットとし、端末全体の背景色は変更しない。
- autoは認識可能な`COLORFGBG`があれば背景を選ぶ。判別不能なら端末の標準文字色と選択の反転を使い、背景色問い合わせのために入力を読み取らない。不正値は対話画面開始前に値の修正方法を示す。非対話コマンドは影響を受けない。
- `NO_COLOR`を最優先し、配色・反転の制御を出さず、記号・文字・列見出しで区別する。テーマ設定のための永続設定ファイルや追加ライブラリは設けない。

## 守る契約と検証

- Proxyの所有権、署名付きstatus/stop、起動・終了順序、接続集合、ポート予約・編集の排他、保存形式Version 1は維持する。
- 4形式のエクスポート、実ポート・対象設定の固定、既存ファイル非上書き、保存だけでは接続しない動作を維持する。
- 主対象は`presentation.go`、`selection.go`、`diagnostics.go`、必要なApp入口の`cli.go`、対応する既存テスト、README。`sessions.go`は診断のコマンド集合をSnapshotで安全に複製する補助変更だけを許容する。新規の製品ファイルは上記`clipboard.go`だけを想定し、セッション制御・設定永続化の構造変更は行わない。
- focused検証は表示の文字列だけでなく、検索した操作の確定、無効操作、戻り先、背景イベントとの対象保持、コピーの日本語・引用・取消・失敗、更新中のタブ維持、画面サイズ変更、テーマとNO_COLORを保護する。
- 最終候補で全体race、installer関連race、通常/installer vet、gofmt/diff、CLI5環境・installer3環境ビルドを確認する。偽gcloud/Proxyと一時設定でカラー・light・NO_COLORのPTYを使い、複数接続、検索・消去、メニュー、ヘルプ、復旧・再試行、出力・保存・ポート変更、Ctrl+Cと外部接続維持、画面復元を検証する。
- 設計・実装は現在の担当が直列に継続し、実装者とは別のReviewer1名で監査する。指摘修正後は同じReviewerで再確認し、最終gateの候補を固定する。別のユーザー所有Taskは作らない。
- 実DB接続、DBツールGUI取込、Windows実機でのクリップボード・GUI動作は自動検証と区別して報告する。版番号変更、push、PR、マージ、リリース、端末のインストール更新はこの設計の実行範囲に含めない。
