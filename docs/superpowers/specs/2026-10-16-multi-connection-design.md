# 1画面での複数接続管理

状態: 2026-10-16、ユーザーが設計を承認し、実装計画の作成へ進むことを明示した。製品コードは未変更。
基準: 公開main `f96975546423c6d5df289c563a9e4e477cb54267`（v0.2.3）。元の作業場所にある既存の変更と過去の非公開履歴は保持する。

## 目的

利用者は1つのcsql画面で接続先を追加し、複数DBへ同時接続して、それぞれを個別に停止したい。
別の端末を接続先ごとに開く操作を不要にし、現在の検索、保存済み設定、接続ログ、エラーの対処案内、pgAdmin出力を引き続き利用できるようにする。

## 方式

| 方式 | 判断 |
| --- | --- |
| 既存TUIに接続一覧を追加し、この画面が起動したProxyを接続ごとに管理 | 推奨。稼働中の接続を保ったまま追加・切替・個別停止でき、既存のProxy管理を利用できる |
| 初回の複数選択だけで一括接続 | 起動後の追加や接続別の操作が不足するため採用しない |
| 常駐サービスを設け、CLI終了後も接続を維持 | 今回の目的を超え、配布・認証・所有権の管理が増えるため採用しない |

## 画面と操作

一覧に「インスタンス」「保存済み設定」「接続一覧」の3タブを設ける。Tabで切り替え、接続一覧には稼働件数を表示する。

- インスタンスまたは保存済み設定からEnterで接続を追加する。他の接続は維持する。
- 接続の詳細から「追加」で選択画面へ戻る。接続開始待ちの間でも別の接続先を選べる。
- 接続一覧は、接続先名、プロジェクト、ローカルポート、状態を表示する。選択してEnterで詳細を開く。
- 状態は起動中、接続確認中、Proxy利用可能、接続エラー、停止処理中、停止済みを区別する。「Proxy利用可能」をDBログイン成功とは表示しない。
- 接続の詳細では、選択した接続のログ・対処案内・保存・pgAdmin/URI出力・再試行・停止を扱う。
- 詳細のEscは、接続を止めず一覧へ戻る。停止は明示された「選択した接続を停止」操作で行う。従来のEsc停止からの変更を画面とREADMEへ明記する。
- 一覧でEscを押した場合、所有する稼働中の接続があれば接続一覧へ戻る。稼働中の接続がなければ終了する。
- Ctrl+Cは、この画面が起動した全接続を停止して終了する。終了操作のガイドには「全接続停止」を明記する。
- 停止済み・エラーの接続は実行中の画面に残し、詳細から再試行できる。接続一覧自体の履歴保存は追加しない。

広い画面の一覧と詳細の2ペイン、狭い画面の1列表示を継続する。60列×16行を対応範囲とし、接続件数が増えても選択行へスクロールできる。
操作ガイドと更新通知を保持し、選択状態やエラーを色だけで区別しない。
検索欄・フォーム入力中の文字入力を、追加や停止のショートカットとして誤認しない。

## 接続ごとの独立性

各接続は独立した識別子と試行番号、子プロセスの取消、進捗、ログ、エラー、再試行状態を持つ。
画面の選択先を変えても、起動・停止の完了や遅れて届いたログは元の接続にだけ反映する。
1件の認証失敗、ポート競合、起動失敗、異常終了、個別停止は、他の接続や検索を中断しない。
接続していない検索処理のエラーも、稼働中の接続を停止させない。

再試行は対象の古いProxyの終了を待ってから開始する。停止処理中の二重起動を防ぎ、古い試行の完了結果を新しい試行へ反映しない。
同じインスタンスを同じ接続方式・ポートで追加しようとした場合は、既存の接続詳細へ移動する。
すでに同じインスタンスへ接続中で、要求する接続方式や明示ポートが異なる場合は、既存接続の情報と必要な操作を案内し、黙って停止・切替しない。

終了時は開始済みの全workerと所有Proxyの終了を待って、元の端末画面を復元する。
既存の終了待機と強制終了の契約を利用する。起動直前・起動中・保存中・停止中の終了でも、後からProxyが残留しないようにする。

## ポートと保存済み設定

既存の固定ポート予約を維持する。保存済み設定のポートが使用中でも、別のポートへ自動変更しない。
保存していない接続のポートは、既存のDB種別ごとの範囲から割り当てる。
同一画面内で同時に起動を追加しても、起動待ちを含む自分の接続同士で同じポートを割り当てない。
起動失敗や停止時のポート予約は、所有プロセスの終了を確認してから解放する。他のプロセスとの競合は対象接続のエラーとして案内する。

保存フォームを開いた接続と、保存・出力の対象を固定する。別の接続の完了通知がフォームの対象や入力内容を変更しない。
稼働中の接続を保存する場合は、実際の待受ポートを使う。接続中のポート変更は引き続き拒否する。
プロファイルの保存形式、既存プロファイルの名前とポート予約、pgAdmin JSON・URI形式は変更しない。

## 所有権と既存機能

この画面が起動した接続だけを、画面内の一括終了で停止する。別端末・別プロセスが起動したProxyを勝手に取り込んだり停止したりしない。
別端末の `csql status` / `csql stop SESSION_ID` は引き続き各接続へ使える。外部から停止された場合も、その接続だけを停止済みとして表示する。
制御通信の署名、トークン、管理記録の形式は変更しない。

非対話実行の既存コマンドは維持し、複数接続用の新しい引数やバックグラウンド常駐機能は追加しない。
`profile add` は設定を追加する既存の操作として維持する。起動時の更新確認は1画面につき従来どおり1回とし、接続追加のたびに通信しない。
認証・IAM・実DB・DBブラウザ内部の設定は自動変更しない。

## 受入条件と検証

1. 1画面から2つ以上の接続を起動でき、別々のローカルポートで待受できる。
2. 接続追加、一覧移動、詳細切替、検索によって既存接続が切れない。
3. 選択した1件の停止・失敗・外部停止・再試行が他の稼働接続へ影響しない。
4. 同時追加や停止直後の再試行で、ポート・接続識別子・ログ・遅延結果が混線しない。
5. 接続ごとの保存とpgAdmin/URI出力が正しい接続先・実ポートを使用する。
6. Ctrl+Cや外部取消で、この画面の全Proxyが終了し、管理記録と端末状態が後片付けされる。他の画面のProxyは維持される。
7. 60列×16行、日本語入力、色なし表示、既存単一接続・検索・認証案内・更新通知が維持される。

検証には偽gcloud/Proxyと一時設定を使い、実GCP・実DBへは接続しない。並行起動、個別停止、取消の状態遷移をfocused testとrace検証で確認し、PTYで一連の操作を確認する。
実装後は独立レビューと同一候補での最終検証を行う。Mac・Windows用インストーラーへ同梱できることもビルドで確認する。
